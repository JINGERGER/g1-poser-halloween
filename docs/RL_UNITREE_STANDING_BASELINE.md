# Unitree官方G1基线：先复现，后迁移

## 固定来源与边界

- 仓库：`https://github.com/unitreerobotics/unitree_rl_gym.git`
- 固定提交：`276801e46c5d433564f24658bac64f254b7d2d4b`
- 配置：`deploy/deploy_mujoco/configs/g1.yaml`
- 权重：`deploy/pre_train/g1/motion.pt`
- 模型：`resources/robots/g1_description/scene.xml`，包含`g1_12dof.xml`。
- 原始部署：`deploy/deploy_mujoco/deploy_mujoco.py`；原始BSD-3-Clause许可证保留在下载目录。

这是开源运动策略，不是Unitree商用内置站立模式，也不是我们自己训练的权重。
当前仅复现官方12关节模型，未迁移到改装23执行器模型，不改变已有爬行发布版。
上身在官方模型中的表示不同，不能将原模型结果当作改装机器人的站立证据。

## 接入契约

- 12个腿关节，47维观测；保留角速度、重力方向、速度指令、关节状态、上一动作及0.8秒周期相位。
- PD比例增益为100/100/100/150/40/40（双腿相同），阻尼2/2/2/4/2/2。
- 默认关节角为每腿`[-0.1, 0, 0, 0.3, -0.2, 0]`，动作缩放0.25。
- 原版MuJoCo的MjData零关节状态启动，不额外设置为默认角、不调整落地高度。
- 2ms物理步长，每10步物理执行后更新策略，首10步先向默认姿态施加PD力矩。
- `ctrl`为力矩，不是位置目标；保留官方模型的限力机制，不增加额外截断。
- 运行10秒仿真时间，而非GUI墙钟时间；物理诊断在独立MjData上计算，不改变运行状态。
- `get_gravity_orientation`与`pd_control`从已检查的固定源码提取，不导入训练框架。
- 原始仓库必须干净且HEAD匹配；报告记录配置、权重、源码、模型/mesh哈希及依赖版本。

## 复现

先准备固定参考仓库（已有目录时不要重复clone）：

```bash
git clone https://github.com/unitreerobotics/unitree_rl_gym.git output/rl/reference_assets/unitree_rl_gym_276801e
git -C output/rl/reference_assets/unitree_rl_gym_276801e checkout --detach 276801e46c5d433564f24658bac64f254b7d2d4b
uv run --extra crawl --python 3.13 --with PyYAML==6.0.3 python -B rl/check_unitree_baseline_contract.py
uv run --extra crawl --python 3.13 --with PyYAML==6.0.3 python -B rl/check_unitree_standing_baseline.py
```

不安装官方训练框架；PyYAML仅为此诊断临时依赖。下载资产和结果保存在忽略的`output/`。

契约测试直接执行未修改官方部署脚本，仅替换viewer、sleep及根路径模块；
500个物理步的关节/基座状态与ctrl均和无窗口适配器匹配至1e-10。
每次正式运行另外用保存ctrl重放全部物理步，qpos/qvel匹配至1e-10。

| 默认角恒定PD | 1.26秒触发倾斜紧急停止 | 只否定原版MjData起点下的这段恒定PD保持，不否定官方完整站立流程 |

零指令下，1秒后最大水平偏移约0.224m，双脚同时载荷>5N的采样占比约10.5%。
原地双脚持续承重、位置保持、末秒低速度门槛未通过。因此不能直接把零指令当作稳定站立端点。
零指令与前进案例最大穿透分别约6.36/6.54mm，超过我们现用5mm筛选门槛，
且并非只在初始化瞬间发生。保留官方接触配置，不为过门槛修改参数。
三例全部通过逐步控制重放；原版部署契约检查也通过。

站立门槛是本项目的严格筛选，不是官方认证标准。未设置跌落恢复或随机扰动实验。
当前指标不提供硬件安全结论，也未声称零指令策略足端完全不动。

## 下一步决策

官方策略值得保留作动态平衡/运动基线，但不是现成的静止站立控制器。
下一步在同一改装模型上做明确的12腿关节映射，其他关节固定在已审计姿态；
务必显式转换位置执行器与力矩执行器契约，保留原限力/惯量/碰撞，记录任何执行器修改。
先比较零指令运动表现与已有原生PD站立，不直接拿去接手过渡或覆盖现有控制器。
若需要静止站立，后续再考虑零指令相位/奖励适配或独立平衡策略，不能在本轮偷偷修改相位。

## 改装模型迁移首轮（2026-10-23）


### 执行契约

- 三例共用改装模型、屈膝0.6rad初态、零初速度；保留接触时间常数0.005、2ms物理步长。
- 根据官方模型关节名称建立12腿关节映射，不把全部23维关节状态直接送入47维观测。
- 上身11个关节继续使用原生位置执行器，保持同一初始目标。
- 官方两例仅在内存中把腿部执行器改为单位增益、无位置反馈偏置的力矩输入。
  取消腿部原本按角度定义的ctrl截断，保留真实关节限力和执行器限力；并非取消电机约束。
- 碰撞、质量惯量、摩擦、被动阻尼、关节范围及mesh均不变，没有修改磁盘模型或已发布爬行入口。
- 外部显式PD与MuJoCo隐式位置伺服并非数值上完全等价。因此这是完整迁移对照，不是单独PD增益消融。
- 官方两例从官方默认目标启动，RL每20ms物理执行后更新；无动作混合，无相位冻结。
- 该迁移runner沿用本项目站立诊断的逐步mj_forward与验收流程，不冒充原版模型逐位轨迹复现。

### 结果

| 案例 | 结果 | 最大倾斜 | 最大电机限力比 |
| --- | --- | --- | --- |
| 原生PD保持0.6rad站姿 | 5秒严格站立验收通过 | 0.0461rad | 11.74% |
| 官方默认目标＋官方PD | 1.458秒触发倾斜停止 | 0.8024rad | 32.37% |
| 官方RL＋零指令 | 完成5秒，动态直立；严格静止验收未过 | 0.0695rad | 40.95% |

RL例通过本次全过程高度、倾斜、穿透、自碰撞容差、非脚触地、限力与关节范围门槛。
最大总穿透1.755mm、最大启用自碰撞穿透0.763mm；不能表述成完全没有自碰撞。
基座净位移x=-1.85cm、y=-7.14cm，脚部原点最大水平位移10.42cm。
失败项集中在脚位置保持、双脚持续承重和末段低速度；脚位移包含踏步，不应全部称为滑移。
因此应记录为“短时动态直立基线可运行”，而非“官方策略迁移失败”或“静止站立已解决”。

三例保存ctrl重放均逐物理步匹配qpos/qvel至1e-10。
原生对照的qpos/qvel/samples与上一轮0.6rad成功例逐元素完全一致。
接口单测验证关节重排映射、12.5Nm不被角度ctrlrange截断、±1000Nm请求仍受真实关节限力、
上身执行器和物理参数不变，以及非单位传动被拒绝。

### 后续选择

保留两个互补基线：原生PD用于固定站立端点，官方RL用于动态平衡/踏步对照。
不为满足“完全不动”门槛而擅自冻结策略相位，也不删除碰撞或增加电机限力。
下一步用有限的受控扰动与短时姿态降低试验评估可用范围，并允许重新选脚位置/接触顺序，
不继续坚持上一轮固定双脚、手直线下移的失败IK参考。
在进入过渡训练前必须明确选择控制接口：本次官方腿部力矩接口不能直接接收现有爬行位置目标，
需要显式切换/统一伺服并审计目标和力矩突变，不能仅把两个策略的动作向量拼起来。

### 预先固定的六组

1. 原生PD保持基线。
2. 官方零指令RL基线。
3. RL在2.0–2.2秒受世界x方向15N骨盆外推，冲量3Ns。
4. RL在同一时段受世界y方向15N外推，冲量3Ns。
5. 原生PD在2–3秒平滑叠加膝+0.2rad、髋/踝俯仰各−0.1rad，随后保持到5秒。
6. 官方RL叠加同样的物理目标偏置，策略观测默认角、相位、上一原始动作均不更改。

两组推力是明确的外部扰动，不是扶持。其他组全程无外力，不直接改写状态。
每个物理步保存外力与ctrl，重放两者后qpos/qvel匹配至1e-10；记录的外推冲量核对为3Ns。

恢复筛选允许继续踏步，而不是强求双脚静止：必须通过全部动态物理门槛，
末秒线速度RMS≤对应基线+0.05m/s、角速度RMS≤基线+0.1rad/s、倾斜RMS≤基线+0.03rad，
与无扰动基线的末秒水平位置差≤15cm。这里的“恢复”仅指此有限时间窗与容差，不保证回到原点。
降低试验要求物理门槛通过，且最后1秒平均骨盆高度比同控制器基线降低至少1cm。
没有用瞬时下落、摔倒或身体倾斜替代受控降低；静态站立门槛仍另列。

### 结果与解释

| 案例 | 结果 |
| --- | --- |
| 两条原基线 | 行为保持不变；原生静态保持、RL动态直立 |
| RL正向/侧向短推 | 两例均通过上述恢复与物理筛选 |
| 原生PD降低 | 末秒平均降低2.500cm，全部物理及静态门槛通过 |
| RL加屈膝偏置 | 虽平均降低8.648cm，但物理筛选失败，不能计为成功下蹲 |

RL偏置案例5秒内净后移约82.1cm、侧移47.8cm，最大脚原点位移约98.6cm，
最大倾斜0.1734rad（上限0.15）、最大自碰撞穿透1.712mm（上限1mm）。
没有因“5秒没倒”而接受该案例，也没有继续增加偏置或放宽门槛。
该结果仅否定这一固定目标偏置实现，不代表官方策略不能经适配训练获得低姿态能力。

新增测试覆盖准确外推时窗与冲量、偏置末值、正例恢复、速度未恢复反例、
没有真正降低/只有瞬时降低反例、降低但碰撞反例、最终比较窗口不足反例。

### 下一步不再扩展手工偏置

把原生PD的2.5cm受控降低作为已有物理执行证据/短段参考，不能当作完整站立到爬行演示。
官方RL保留为动态平衡对照，不假设简单叠加关节偏置就能完成接手动作。
下一阶段应建立独立过渡任务，以实际接触转换和冻结爬行控制器接管为终端目标；
先统一或显式切换执行接口，再用已验证短段初始化课程，允许选择脚位置而非锁死失败IK路线。
完整手接地、增益交接及爬行接管仍未实现，本轮没有训练新策略。
