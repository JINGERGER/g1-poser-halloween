# 固定预算卸载学习曲线

## 预定协议

延续 `G1UnloadObjectiveV1` 的模型、初态、动作、奖励、严格终止及完整短步验收，不调参。
两个种子均从头训练，8环境×24步×256更新=每种子49152 transitions，总98304。
在64、128、256更新后保存检查点，对应12288、24576、49152 transitions。
这是上一档预算的4倍，不是无限续训或依据最好结果提前选点。
训练结束后再评估三个检查点，避免评估影响训练随机数流。
只保存权重与审计快照，不提供优化器续训承诺；本轮不恢复任何旧检查点。

## 记录与验收

新增 `G1UnloadCurveV1` 仅增加训练episode统计，继承原卸载目标环境。
记录完成/未完成episode、事件最大阶段、严格失败原因、载荷最小值及卸载时长估计。
卸载时长使用控制步端点近似，不是2ms子步连续卸载证明；阶段事件仍使用原物理子步判据。
训练统计包含随机策略，严格检查点评估使用确定性均值策略，两者分开报告。
episode按终止所在更新窗口统计；跨窗episode不被拆成独立样本，末尾未完成episode不算失败。

三次验收全部调用冻结的 `evaluate_short_step.py`，包含保持、零残差IK、减载回撤基线。
主要看卸载/离地/前摆/回载阶段与严格成功；载荷下降、回报上涨、保持时间增长只是辅助证据。
同时报告0.4–2.6s载荷均值，并标记窗口是否完整，避免早停轨迹与完整轨迹误比。
两个种子与一条名义均值轨迹不构成泛化成功率。

固定停止点：256更新后结束，不因曲线好坏自动增加预算或修改奖励。
若阶段仍为0，需要结合随机训练中的事件统计判断是探索未到达还是均值策略没有保留事件能力，
不能仅看最终均值轨迹就声称训练中从未发生卸载。

## 实现与检查

- `rl/unload_curve_task.py`：只读episode统计，不改变环境输出。
- `rl/train_unload_curve.py`：固定预算、有限更新检查、64/128/256更新权重快照。
- `rl/run_unload_curve.py`：两个种子与所有预定检查点评估。
- `rl/check_unload_curve.py`：440次成对transition完全匹配奖励/状态/终止/自动reset，统计完整性通过。
- `rl/check_unload_curve_report.py`：逐环境transition账目、配置/源码/权重哈希、全部24条评估原生重放。

原短预算训练入口及其源码哈希保持不变，新增入口不影响历史证据。

### 验证与决策

- 两种子transition逐环境账目完整，终止episode和未完成episode没有重复或漏计。
- 512次PPO更新有效，三个快照/种子与训练前缀指标相符。
- 24条严格评估轨迹原生重放通过，匹配状态、奖励、事件和终止。
- 既有卸载奖励480-transition接口检查及新增440-transition透明记录检查通过。
- `git diff --check`通过。

预算增加确实改善了部分减载，但不是单调提升稳定性；这档预算内随机探索也从未到达完整卸载。
停止追加同方案训练，不从六个检查点中挑最好者冒充最终能力。
下一实验应围绕反复出现的左前臂接触核查动作/任务目标与几何关系，
区分奖励引导方向和模型/接触定义问题，再预先选择一项可检验的变更。
不直接放宽非支撑阈值，也不据此宣称改装G1物理上不可行。

后续逐2ms定位见 `docs/RL_FOREARM_CONTACT_AUDIT.md`：两个最终策略均在打印壳体末端边缘
第一次轻载接触时被终止，不能把此门槛失败直接称为摔倒；平地最低点与原配准CAD一致。
