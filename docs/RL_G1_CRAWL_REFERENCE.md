# 改装 G1：g1_crawl 参考基线核对（2026-10-15）

## 范围与决定

按用户确认，以 `jloganolson/g1_crawl` 为主要参照，不以标准 29-DoF G1 替代改装机器人。
参考提交固定为 `935e8b9c857bd494b952603c0453800a0cf5c9d2`。
本节记录前序只读审计：当时不训练、不改变模型/PD/限矩、不执行外部 Python、不恢复参考仓库已暂存删除的文件。
只通过 `git show COMMIT:path` 检查源码，工作区状态前后完全一致。

`rl/audit_reference.py` 以 AST 读取配置、解析 XML 并按名称比较当前编译模型，
生成 `output/rl/reference_audit.json`，包含来源 SHA256、关节重排表和逐关节参数。
静态解析不能代替加载 Isaac Lab/USD 后的运行时校验。

后续已实现独立 `G1CrawlReference23` 并完成 A/B 短跑，见 `docs/RL_EXPERIMENT_MATRIX.md`。
重要更正：`mdp/events.py:948` 的 `reset_from_animation_frame` 在抽样后结束，
未应用所选帧。此前把配置意图当成已实现的 reset 行为不准确；这不意味着框架完全没有 reset。
审计报告现保存该函数的行号与调用列表。本地任务补全意图并作地面投影，明确标为修改。

## 关键差异

### 1. 训练模型、回放模型、当前训练副本不能混为一谈

- 参考训练加载 `assets/g1_23dof_simple-forearm.usd`；该文件在本地提交中仅为 LFS 指针，
  指向约 39.97 MB 文件。因此尚不能验证参考训练的实际质量、惯量和碰撞网格。
- 参考 MuJoCo `scene.xml` 为 21 执行器，缺两个 wrist_roll；policy 接口为 23 关节。
  **纠正此前判断**：runner 的 `_remap_mujoco_to_pytorch` 对缺失腕关节补零，
  `_remap_pytorch_to_mujoco` 丢弃对应输出。这是显式适配，并非必然维度报错。
  但有真实腕关节的当前 23 执行器模型与这种回放仍不等价，不能直接套用其重排结果。
- 当前 23 个执行器与 policy 关节名集合一致，已生成双射索引；这只证明名字可映射，
  不证明轴方向、动作语义或动力学兼容。
- 参考回放手球半径 2 cm，当前训练副本 3.5 cm；参考训练 USD 的实际球尺寸待验证。
  参考回放手球还显式声明 condim=1；实际接触维度要结合地面/优先级在编译模型中核对，
  不能把该回放 XML 当成 Isaac Lab 接触参数的真值。
- 参考训练 `enabled_self_collisions=False`；当前训练只排除两对上臂/前臂碰撞。
  不为追求训练效果而直接关闭所有自碰撞；任何这种实验须单独标注模型差异。

### 2. PD 增益明显不同，限矩并没有放宽

下面为参考训练配置的数值与当前 MuJoCo 模型数值，不包括回放器 1.4 倍增益：

| 关节组 | 参考 Kp / Kd | 当前 Kp / Kd |
|---|---:|---:|
| 髋 pitch | 40.18 / 2.56 | 350 / 5 |
| 髋 roll | 99.10 / 6.31 | 200 / 5 |
| 髋 yaw | 40.18 / 2.56 | 200 / 5 |
| 膝 | 99.10 / 6.31 | 300 / 10 |
| 踝 pitch | 28.50 / 1.81 | 300 / 5 |
| 踝 roll | 28.50 / 1.81 | 150 / 5 |
| 肩、肘、腕 | 14.25 / 0.907 | 40 / 3 |

- 全部 23 关节正向限矩与参考配置一致，手臂均为 25 Nm。
- 上次“参数保持原模型不变”指保持我们自己的 poser 参数，不意味着与参考训练参数一致。
- 参考 Isaac Lab 使用 implicit actuator，当前为 MuJoCo position servo；同数值也不保证
  同物理效果。参考回放器额外乘 1.4 的行为不能当作参考训练原值。
- 当前优化 home 相对参考默认关节角最大差约 0.0946 rad，来自髋 roll；不是直接使用原始默认姿态。

### 3. 学习任务并不相同

| 项目 | 参考注册任务 g1-crawl | 当前 Direct V2 |
|---|---|---|
| actor / critic | 按 23 关节推导 75 / 81 维，非对称 | 85 / 85 维，同一观测 |
| actor 速度信息 | 无基座线/角速度 | 世界线速度及 gyro |
| 相位 | actor 中被注释，没有强制逐肢相位奖励 | 周期 4 秒，逐肢相位支持/抬升奖励 |
| 动作 | 默认角 +0.5×动作，runner clip_actions=5 | 默认角 +0.5×动作，env 裁剪 [-1,1] |
| 初始化 | 配置意图为 animation_rc4 随机帧和扰动，但选帧函数未写回状态 | 优化 home，关节小噪声 |
| 速度命令 | 基座局部 [vz,vy]，世界 z 转向；定期重采样 | 世界 x 的低速标量，每回合固定 |
| 终止 | 当前源码仅超时 | 高度/姿态/躯干及其他非末端接触 |
| 控制周期 | .005 s×4=.02 s | .002 s×10=.02 s |
| actor/critic 网络 | 256/128/128，初始 std=1.0 | 128/128，初始 std=0.3 |
| 对称增强 | 数据增强及 mirror loss=0.5 | 未使用 |

- 参考速度字段名字 `ang_vel_x` 不应直接当成实际旋转轴：激活的奖励函数为
  `track_ang_vel_z_world_exp`。俯身后坐标轴发生变化，移植必须以公式/旋转矩阵为准。
- 参考 actor joint_vel 未配置我们这里的 0.05 缩放，75 维也不是删掉当前十个通道即可。
- 参考 foot_clearance 奖励被注释；主要使用速度/姿态、滑移、关节/力矩约束及双肢同时腾空惩罚。
  不能把“改成更多抬脚奖励”说成复现这个参考。
- 实现动画随机帧初始化时，它只是状态分布先验，不是持续写 qpos，也不等于动作参考跟踪。
  动画本身仍需在当前改装模型上核对接触、限位和物理有效性。
- 参考源配置默认 4096×24×1000=98304000 transitions，是我们每轮 307200 的 320 倍。
  不代表最终发布策略真实训练预算；作者也声明最终策略的精确奖励配置不完全确定。

## 最小推进方案

1. 保留现有结果，名称仍为本地自定义诊断，不能重新标成 g1_crawl 复现。
2. 先明确两种资产的角色：需要核对的是参考训练 USD 与真实改装结构，不是盲换回放 XML。
   实际手球尺寸、前臂改装质量/惯量仍需实物资料；没有资料时必须标为仿真假设。
3. 已完成**参考 PD 数值的短物理对照**，保持几何、限矩和初始化不变；
   单独替换参考增益让固定目标躯干更早触地，不能直接替换现有默认值，结果见下节。
4. 再确定移植契约：无强制相位的 actor/critic 分离、名字映射、基座命令坐标、
   动画帧 reset 和必要的噪声/对称机制。安全终止若保留，显式记录为对参考的修改。
5. 控制契约通过后才制定与 Mac 吞吐相符的训练预算；不把 300 轮失败当成参考算法失败。
   不依赖取得完整外部策略，也不在本轮同时改 PD、碰撞和奖励后直接开训。

## 仅 PD 数值变化的配对物理测试

新增 `rl/check_reference_pd.py`，报告 `output/rl/reference_pd_check.json`。
加载两份同一 XML 的内存模型，只在其中一份改变位置执行器 Kp、Kd，
不修改 XML 文件，不加载旧策略。复用相同 home 控制目标及五个初始化条件：
无噪声，以及 seed=101/102/103/104 的 ±0.01 rad 关节噪声；各运行 10 秒。

验证边界：
- 比较两模型全部 NumPy 数组，仅 `actuator_gainprm` 和 `actuator_biasprm` 不同，
  且仅 Kp、-Kp、-Kd 所在列变化。几何、质量、关节被动阻尼、armature、自碰撞、限矩均不变。
- 五对初始 qpos/qvel/ctrl 哈希分别相同；源 XML 哈希前后相同。
- 在 ±0.05 rad/零目标偏差与非零速度下，原生力矩与解析重建误差小于 1e-6 Nm；
  实际数值分别为 0 和约 6.94e-18 Nm。运行中重建检查也通过。

| 指标（五个初始化） | 当前 PD | 参考训练 PD 数值 |
|---|---:|---:|
| 首次非末端触地 | 6.02–6.22 s | 1.28–1.46 s |
| 首次触地部位 | 躯干 | 躯干 |
| 最后两秒平均非末端法向负载 | 40.6–41.1 N | 114.5–115.5 N |
| 全程采样峰值力矩/限值 | 76.4%–76.8% | 34.6%–36.4% |
| 纯四肢支撑筛查通过 | 0/5 | 0/5 |

参考 PD 的力矩更低、末段运动更少，但这是在躯干承担更多重量的情况下，
不能按“更静止/更少滑移/更小力矩”宣布更好。两组都不是合格的固定目标支撑。
这些结果只说明**参考增益单独放到我们当前模型与 home 目标上没有解决支撑问题**，
不说明参考 RL 不可行，也不说明低增益在配套策略、默认角和模型下不合适。

**决定：** 不改现有默认 PD，不搜索增益网格，不再把固定 PD 稳定作为训练的硬前置。

不加载旧 85 维策略、不为了得到低力矩而降低增益，不同时改动碰撞和奖励。
