# 新初态的冻结控制敏感性复查

## 协议

冻结`RL_COMPONENT_INITIAL_STATE.md`成功分支的完整初始物理状态和150帧控制序列。
不重新求平衡、不改变控制器、不更换初态，固定5个配置，每个3秒，总计15秒诊断仿真。
开始前将配置与阈值写入报告。

实现：`rl/component_sensitivity.py`；独立复查：`rl/check_component_sensitivity.py`。
报告：`output/rl/component_sensitivity/2026-10-19_20-27-11-730808/report.json`。
模型仍为`component_hulls_v1_12d607bfdb588900`，20mm手球和分部件凸包，未改默认场景。

接触变体将全部geom的正值solref第一项乘以0.8或1.2，第二项及其他参数保持不变。
报告记录实际生成接触的solref、solimp、摩擦与维数，不仅记录输入参数。
原5mm筛选门槛保持不变；诊断允许继续到20mm紧急终止阈值，**不表示放宽接受标准**。

5个配置均完成3秒诊断，未出现非指定部位承担地面载荷。
24ms变体末态四肢载荷约91.26/49.81/34.79/136.27N，平均载荷加权滑移约0.382mm/s，
没有观察到倒地，但最大穿入超过5mm，因此仍记录失败。
失败不应被描述为“完全失稳”，也不能因为没有倒地就改记通过。

## 可以得出的结论

- 本次保持在时间步减半和求解迭代翻倍时结果接近；没有发现它只依赖2ms粗步长或50迭代的迹象。
- 原配置轨迹与上一轮逐帧一致，说明输入冻结和重放链条有效。
- 接触时间常数+20%时超过原穿入阈值，说明当前通过结果的接触参数裕量不足。
- 4/5通过不是概率估计，也不是鲁棒性认证；没有测试随机扰动、摩擦变化、质量误差或长时间保持。
- 这些都是同一候选模型内的保持，不证明硬件、动态可达或完整爬行。

## 下一步决策

不为了恢复5/5通过立即增大刚度、放宽穿入阈值或重新优化各变体平衡。
将当前状态标记为“名义保持已验证、接触参数鲁棒性未通过”，保留为受力诊断入口，暂不作为RL成功数据。

下一项仍是固定该姿态，对四种肢体卸载进行整体受力筛选：检查浮动基座力/力矩平衡、
摩擦约束、执行器目标范围在当前关节姿态可实现的力矩区间。
该筛选是理想化静态能力分析，不承诺原生软接触能实现所求载荷分配，亦不绕过上述敏感性失败。
先用承重能力结果决定移重方向，不继续围绕5mm阈值微调保持器。
