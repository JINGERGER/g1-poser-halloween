# 承重目标的单变量对照

## 假设与边界

检验：人为左右手70/80N目标是否是当前卸载瓶颈。
不是重新训练，不调整权重、预测时长、控制增益、手部约束或物理模型。
两分支从上一轮同一真实完整状态出发，保留速度；各3秒、最多30次规划/1530次预测。

参考来自 `support_order_matrix/2026-10-19_15-16-28-804740/report.json`：
固定选择anchor2、左脚腾空的已通过3秒原生保持分支，取最后2秒100帧载荷均值，
不是挑选最佳一帧。保持卸载目标5N不变，从右脚目标扣除5N，保持总载荷。

- 原目标：`[70, 80, 5, 157.14439] N`。
- 三肢保持均值：`[83.19579, 47.31503, 0, 181.63357] N`。
- 新目标：`[83.19579, 47.31503, 5, 176.63357] N`。

该三肢保持从假设静态姿态初始化、左脚净空13.18cm；它不证明从当前姿态可达。
新目标仅作为承重分布参照，不是已验证的过渡路径或成功爬行示范。

## 实现与复现

`rl/target_load_ablation.py`复用冻结的DirectionalPredictor，单独复制执行循环并显式传入目标，
不修改历史报告依赖的源文件。原目标分支必须逐帧复现历史qpos、qvel、ctrl（误差≤1e-9）。
两份输入报告、模型及依赖源码均校验SHA256；结果保留失败分支与完整轨迹。

## 决策与后续整体验证

后续支撑几何检查见 `RL_TRANSITION_GEOMETRY.md`：旧静态终点还改变了支撑布局，
不能直接当固定支撑的移重目标；当前接触区域对应的最近5mm内缩质心目标仅需水平偏移3.31cm。

本轮不支持“仅换成静态终点承重目标就能解决卸载”。不能据此证明目标无用，
更不能证明机器人无法爬行：只检验了一个初态、固定局部反馈和短预测窗口。
停止继续微调这一局部载荷控制器；不增加同路线随机种子或训练步数来掩盖问题。

下一步应改变问题表示：显式规划从四肢承重到三肢支撑的身体/关节过渡，
让载荷成为动力学结果而非唯一导航目标。先预注册少量不同移重路径，再做有限预算原生回放：

1. 使用实际初始速度和已验证静态三肢姿态，提取身体、支撑点、关节变化；先检查可达性和支撑几何。
2. 对比保持基线、先移重后卸载、联合移重卸载；固定总仿真/优化预算，不沿用已失败的直接关节插值作为唯一方法。
3. 保留电机控制范围、限矩、接触/穿透约束；不允许外力、写入实时qpos或重置速度完成过渡。
4. 分开验收安全、持续卸载、正净空、落脚及身体前移。只卸载到5N不算抬脚，更不算爬行。
5. 若有限路径均失败，记录主导约束，回到全身轨迹优化/模型与执行器审计，不再局部载荷调参。

此后续方案尚未执行；只有通过动态过渡的轨迹才候选为RL物理参考，IK仅作几何先验。
