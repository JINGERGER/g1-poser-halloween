## 2. 接管条件是否必要

实现与集成检查：`rl/check_handoff_window.py`。
报告：`output/rl/handoff_window/2026-10-26_16-53-23-336198/report.json`。

使用此前通过几何筛选的低姿态：名义爬姿骨盆抬高5cm、减小前倾0.2rad、双手目标抬高4cm。
这不是站立姿态。初始速度为零；每次试验从同一初态连续物理执行，不在中途重设状态。
沿原来的关节参考执行0/40/80/120/200ms，比较：

1. 诊断分支：立即交给冻结爬行控制器；仅此分支绕过启发式ready门槛。
2. 对照分支：继续原参考，达到现行ready条件再接管，最长等到2s。

两分支在分叉处的完整 `mjSTATE_INTEGRATION` 哈希完全一致。
所有轨迹保留原2ms物理门槛、2s接管后爬行、连续合格周期及前进6cm要求，并精确重放qpos/qvel。

| 参考前缀 | 接管前ready | 立即接管后2s前进 | 主要被拒原因 |
| --- | --- | --- | --- |
| 0ms | 否 | 0.821m | 双手未接触、没有100ms历史 |
| 40ms | 否 | 0.858m | 双手未接触、混合速度范数0.600、历史不足 |
| 80ms | 否 | 0.864m | 仅单手承重、混合速度范数1.447、历史不足 |
| 120ms | 否 | 0.869m | 四点承重历史不足100ms |
| 200ms | 是 | 0.858m | 无 |

等待分支全部在200ms接管、随后前进0.858m；重复等待分支是确定性对照，不是独立成功样本。
10条轨迹均通过现行物理与功能检查，但只覆盖**同一条低姿态路径上的五个状态**，不代表随机扰动成功率。
80ms时线速度0.369m/s、角速度1.399rad/s；混合范数1.447不应称为1.447m/s。
该状态单手法向载荷约619N；现行门槛没有实机接触冲击/材料应力验收，不能据此宣称落地柔和或适合硬件。

结论：在这些状态，100ms四点承重和混合速度范数<0.5不是冻结控制器成功接管的必要条件。
但这也不证明可以对任意状态删除ready门槛，更不能把这10条计入“站立转爬行成功”。

## 3. 后续方向：达到可接管区域，而不是静态落地姿态

不继续围绕失败策略加局部投影补丁，也不追加原目标的大规模PPO训练。
