# 训练失败与严格验收分离

## 假设与固定预算

初始策略会失稳，不应以“随机策略必须先稳定”阻止训练。本实验直接比较两种训练终止规则，
不要求先构造成功传统控制步态。两个种子，各规则各12288 transitions，总49152；
每次从头初始化，8环境×24步×64更新，不续训、不选最好检查点、不自动追加。
新增环境先执行一次384-transition smoke，不计入对照预算，单独报告。

## 两种规则

原任务 `G1ComponentShortStepV1` 原封不动，作为训练对照及共同严格验收环境。
新增 `G1ExplorationShortStepV1` 仅替换训练终止检查，继承同一模型、reset、148维观测、
23维动作、IK参考、限幅限速、奖励权重、事件顺序及4秒任务期限。
不植入前几轮协调轨迹，避免同时改变多个因素。

| 条件 | 原严格规则 | 探索训练规则 |
| --- | --- | --- |
| 非摆动支撑丢失 | 立即终止 | 记录严格违规，允许继续 |
| 穿入超过5mm | 立即终止 | 记录严格违规；超过20mm紧急终止 |
| 非支撑部位地面载荷 | 超过1N终止 | 超过30N终止，防止持续依靠身体支撑 |
| 瞬时力矩比超过95% | 立即终止 | 不额外终止，模型本身的电机限制保持 |
| 基座高度超出0.16–0.65m、关节限位、自碰撞超过1mm | 终止 | 保留 |
| 非有限动作或物理状态 | 抛错，不静默重置 | 保留 |

20mm与30N只是**未校准的实验紧急截断值**，不是硬件安全标准，也不意味着5–20mm穿入
已经证明物理可信。20mm可能非常大，允许这一区间是有意检验截断规则影响；不能用于验收。
这些阈值写在独立、哈希记录的训练环境代码中，原冻结资产和严格协议没有被修改。
本实验仍保留部分保守终止条件，不是宣称已经设计出最佳跌倒判据。

没有追加严格违规惩罚，保持原奖励不变，以免同时混入奖励设计变化。
训练终止后的重置、terminal reward、final observation语义不变。
训练环境的success只表示其放宽规则下完成事件；对外任务成功只能由独立严格环境确认。

## 评估与验证

每个最终检查点均在严格与探索两个环境运行确定性评估，各带保持、IK零残差、已有减载回撤基线。
名义reset各一条，不宣称统计成功率。主要指标是完整事件阶段与严格成功，不是单纯存活或回报。
新规则使存活变长本身不能证明策略更好；必须看相同严格环境的结果。
保存训练配置、源文件、检查点、评估轨迹哈希和每次PPO有限更新结果。

入口：
- `rl/exploration_task.py`：独立训练终止规则；保留旧严格违规日志。
- `rl/check_exploration.py`：接口、保护边界、reset与事件检查。
- `rl/train_exploration.py`：固定预算训练。
- `rl/evaluate_exploration.py`：放宽训练规则的评估，不能替代严格评估。
- `rl/compare_exploration_training.py`：双种子双规则固定对照。
- `rl/check_exploration_comparison.py`：训练证据及全部评估轨迹原生重放。

新任务仅覆盖step，保留冻结父环境及旧证据；复制的step与训练入口用于隔离此次对照，
不修改UniLab和旧任务。后续整理公共代码必须重新验证冻结行为，不在本次实验中混做重构。

## 已执行结果（2026-10-19）

总报告：`output/rl/exploration_comparison/2026-10-19_21-39-17-849460/report.json`。
前置smoke：`output/rl/exploration_training/2026-10-19_21-38-29-164345/report.json`，384 transitions。
四次screen均完成64次PPO更新，共49152 transitions，无非有限更新跳过或回滚；
每次训练驱动墙钟约31.2–33.5秒，四次约129.5秒，不含评估、检查和授权等待。
没有续训或追加预算。

| 训练规则/种子 | 严格评估 | 放宽评估 | 两种评估最大阶段 |
| --- | --- | --- | --- |
| 严格/1 | 4s截止，无保护失败 | 4s截止 | 0 |
| 严格/2 | 4s截止，无保护失败 | 4s截止 | 0 |
| 放宽/1 | 0.034s穿入超过5mm | 4s截止 | 0 |
| 放宽/2 | 2.270s穿入超过5mm | 4s截止 | 0 |

全部没有完成完整短步，不能把4秒截止当作成功。
严格训练的两个检查点在严格评估中最低左手载荷约66.79/70.27N；
放宽训练在自身评估中的最低左手载荷约80.88/81.29N，最高穿入约5.015/5.295mm。
本次没有证据表明放宽训练已经学会卸载，也不能用更长存活时间证明控制性能提高。

最重要的修正：初始随机探索非常差，并未阻止原严格任务在小预算训练后得到能保持4秒的策略。
因此先前把“初始化策略安全探索”当作训练准入门槛是不合适的。
另一方面，仅改变终止规则没有在这个预算内推进事件；不能由两个种子判定该路线普遍无效。
两个策略族都停留在阶段0，下一次实验应围绕任务进展信号与分阶段学习设计，而不是继续优化
同一条手工安全轨迹或放宽更多阈值。长时间训练的价值尚未通过本次小预算实验判定。

验证：原、新任务接口检查通过；旧冻结评估重放通过。
四个训练报告的配置/检查点/源码哈希与有限更新检查、32条严格/放宽评估轨迹的原生重放
由 `rl/check_exploration_comparison.py` 验证，涵盖状态、奖励、事件及终止语义。

后续已完成同预算的奖励单因素方案对照，见 `docs/RL_UNLOAD_OBJECTIVE_ABLATION.md`。
它保留严格规则并加强连续卸载奖励；两种子有小幅减载改善，但仍未达到第一个卸载事件。
