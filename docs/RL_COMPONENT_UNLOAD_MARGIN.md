# 左手卸载：裕量解与原生接触一致性

## 固定协议

延续上一轮固定姿态与4个接触点，仅执行1次裕量LP（20秒/10000迭代），
再在同一qpos、零qvel下比较原保持ctrl与候选ctrl的原生`mj_forward`结果。
不改变姿态、接触参数、碰撞排除或电机限制。本轮没有`mj_step`、控制轨迹或抬肢。

实现：`rl/component_unload_margin.py`；复核：`rl/check_component_unload_margin.py`。
报告：`output/rl/component_unload_margin/2026-10-19_20-33-37-374564/report.json`。

## 裕量定义

固定左手法向载荷=0，其余三肢≥5N，保持29维平衡与原摩擦约束。
最大化统一标量`t∈[0,1]`：

- 每个电机力矩距离可实现区间两端至少`t × 该区间半宽`。
- 保留接触的每个摩擦菱形面内余量至少`t × 机器人重量/3`。
- 左手已卸载，四个摩擦面必然在零力处相交，因此不要求左手具有正摩擦面裕量。

这是预先选定归一化方式下的内部余量，不是硬件安全系数，也不是“还能多承重14%”。

## 理想化静态解：存在正裕量

- 最优`t = 0.144517`。
- 最小电机力矩边界距离约**3.613Nm**，不再处于原力矩边界。
- 保留接触的摩擦菱形面余量至少约**15.037N**。
- 左手/右手/左脚/右脚载荷约**0 / 143.80 / 101.36 / 66.99N**。
- 29维平衡残差最大约`2.1e-14`；独立世界系合力与绕COM力矩检查通过。

说明上一轮返回的力矩边界解不是唯一可行形式，左手零载荷存在内部解。
但接触点与力仍来自理想静态LP，尚未成为真实软接触载荷。

## 原生接触：未实现该静态解

把目标力矩换算成当前位置下的合法位置伺服ctrl，再运行原生前向动力学：

| 指标 | 原保持控制 | 有裕量候选控制 |
| --- | ---: | ---: |
| 左手载荷 | 90.85N | **17.89N** |
| 右手载荷 | 49.58N | 121.33N |
| 左脚载荷 | 34.82N | 100.68N |
| 右脚载荷 | 136.58N | 73.50N |
| 基座线加速度范数 | 0.00409m/s² | **0.23335m/s²** |
| 角/关节加速度最大绝对值 | 0.0500rad/s² | **47.4819rad/s²** |

候选ctrl均在范围内，原生电机力矩与LP目标逐项吻合（检查容限1e-6Nm）。
因此这次差异不是电机目标换算错误或力矩被截断。
同一姿态下左手仍几何穿入约4.900mm，原生接触求解并不按LP指定的零力分配运行。
候选未通过左手≤1N及近静态加速度条件，不能标为成功卸载。

原保持控制的“卸载通过”标志为false是正常的：它本来就在四肢承重，不是保持失败。
两项均只是time=0的前向探针，不把瞬时预测载荷下降描述成机器人已经完成移重。

## 决策

这排除了“左手卸载只能依赖电机极限”这一解释，但同时验证了：
**有裕量的静态力分配，不能直接替代软接触一致的姿态和运动。**

不将该ctrl直接当作抬手命令，也不继续微调固定姿态下的载荷目标。
下一项只做一个有预算的三支撑原生平衡候选：允许身体/关节姿态一起调整，
让左手实际离开地面，并同时求其余三肢承重和低加速度。
若找到，它仍只是初始化终点，需要另行求从已验证四支撑状态进入该终点的电机过渡。
若失败，记录碰撞、姿态、力矩或接触约束，不由单次局部失败推出机器人无解。

上一轮接触时间常数+20%时穿入超门槛的失败继续保留；本轮未提升鲁棒性或硬件可信度等级。
