# COM反馈停止状态：安全恢复候选审计

## 固定测试

输入：`output/rl/com_feedback/2026-10-19_19-39-34-350779/report.json`。
报告：`output/rl/recovery_audit/2026-10-19_19-43-17-850648/report.json`。

完整重放反馈实际执行的0.1秒，获取真实停止状态，保留速度、时间和ctrl。
复用冻结控制器，重算失败的第二次规划（51次预测），要求其选择/拒绝结果与历史一致。
随后固定检查6个候选，各0.2秒原生诊断预测：

1. 保持停止时当前ctrl。
2. 原拟合得到的4个步长候选：1、0.5、0.25、0.125。
3. 回退到本轮COM反馈开始前的ctrl，即先前真实移重过渡终点的电机目标。

记录全预测区间最小约束裕量、首次违规的20ms采样区间、末速度和COM误差。
穿透在2ms物理子步累计；首次违规时间按20ms区间末端报告，不冒称精确越界瞬间。
所有候选都从同一完整真实停止状态出发；候选预测写入的状态只属于诊断副本。

只有保持或回退候选通过原4.95mm预测门槛，才允许从该真实停止状态做最多3秒恢复回放，
再检查末1秒余量/速度以及额外0.2秒末态保持预测。不允许将被拒绝的4个候选真正执行。
本轮不搜索新方向、不延长预算、不调整阈值或改COM目标。

回退旧电机目标不能回退机器人已经产生的速度和接触状态，故不能默认安全。

这否定的是本轮有限候选集合，不是证明该状态全局不可恢复或机器人不能爬行。

## 整体判断与下一步

问题不在于“停止后多试几次回退”，而在于前一次动作接受没有保证下一次仍有安全后续动作。
此前只有一次短预测通过，没有保留经验证的恢复路径。
继续在该状态微调步长，或允许4.95mm预警线被穿过，会掩盖这个控制结构问题。

下一步回到第一条纠偏动作接受之前，做配对的保护机制验证：

- 对即将执行的0.1秒动作模拟其真实后继状态，再从后继状态检查有限的保持/回退路径；
  不仅检查原动作自身的短区间。
- 没有通过后继安全检查就拒绝第一步，保留原本已验证的保持控制，不能先执行再期待有回退动作。
- 这一检查只是有限时域保护，不声称递归可行性、硬件制动或无限期稳定。
- 若保护机制只能保持而不能推进COM，明确记作任务未完成；再决定是否需要具有更大接触余量的
  上游移重路径，而不是不断增加局部反馈候选或扩大RL训练。

本轮没有任何新的卸载、抬脚或爬行示范；零RL更新。
