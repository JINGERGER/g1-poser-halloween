# 手间负载转移约束对照

## 冻结设计

上一轮左脚降载同时增加左手承重，因此本轮只改变局部反馈的方向约束，不延长预测/仿真、不改变目标权重。
从 `load_feedback/2026-10-19_18-17-40-514548/report.json` 的同一初态出发：
保持目标、原反馈、新方向约束反馈三分支各最多3秒，前两组须复现历史结果。

- 原模型/PD/摩擦/限矩不变，仍预测0.2秒、每0.1秒重规划，最多30次。
- 目标载荷、速度/高度代价、控制正则、±0.015rad信赖范围、有限差分幅度和4个回查步长均不变。
- 在原有界最小二乘目标上加入线性化手部载荷约束，使用最多100迭代的局部二次规划。
- 全预测区间与实际执行端点：左手≤起始左手+0.5N，右手≥起始右手-0.5N。
- 预测末端额外要求：左手≤当前左手+0.25N，右手≥当前右手-0.25N。
  允许微小变化，但不能用持续加压左手/卸载右手换取左脚降载。
- 仍用完整非线性预测检查候选，线性约束通过不等于允许执行。没有合格动作则停止，不放松界限。
- 实际5mm穿透、非支撑载荷、滑移、限矩验收不变；卸载仍要求完整3秒且末0.2秒左脚≤5N。
- 每反馈分支最多1530次预测，零重启、零RL更新。不把保持不动通过方向约束当成任务成功。

这只测试方向约束是否有帮助，不声称已经优化身体质心路径或实现全身MPC。
左右手±0.5N/0.25N是本轮固定控制约束，不是传感器噪声标定结果。

## 整体判断与停止

后续单变量目标对照已完成，见 `RL_TARGET_LOAD_ABLATION.md`：使用三肢保持承重分布后左脚仍有43.51N，
没有优于原目标的41.28N。仅更换载荷目标不足以解决过渡，停止局部目标微调。

方向约束确实抑制了已发现的负担转移方式，但没有找到完整卸载路径。
不围绕41N继续微调权重或延长同一控制，当前也不具备训练“成功爬行示范”的数据。

需要纠正更上层的目标选择：目前左右手70/80N是人为设定，不是已验证三肢姿态的承重分布。
已通过原生保持的候选实际约为 `[83.20, 47.32, 0, 181.63] N`，主要增载的是右脚，而非右手到80N。
该候选13.18cm净空不等于可直接使用的低抬脚路径，但其真实承重分布比任意手部目标更有依据。
下一项应围绕这个已验证终点联合考虑身体位姿、右脚承载和阶段时长，而不把“必须大幅增加右手负载”
误当作必要条件。此前约束仅证明本轮局部安全改进，没有证明新的完整路线必然可行。
