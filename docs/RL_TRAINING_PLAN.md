## 实施顺序与验收门槛

### A. 模型与环境

- [x] 检查爬行姿态、关节限位、四肢碰撞、初始穿透和 PD 支撑；未训练 PD 不稳定，详见记录。
- [x] 独立训练场景：不含 GUI、装饰、IK mocap 和自动回原点。
- [x] 遵循 UniLab registry / NpEnv / SimBackend / reset 契约。
- [x] 动作只写执行器，非 reset 阶段不改根部位置或关节状态。
- [x] 检查 batch reset、观测维度、超时截断、跌倒终止和数值有限性。

### B. 平地四肢爬行

- PPO 首版，先用已验证可工作的 MLX 或 PyTorch runner；小批量确认后再扩大。
- 先训练四肢支撑，再训练 0.05–0.15 m/s 低速前进，之后加入停止/变速。
- 参考抬升高度 0.08 m，不作为地形任务的固定安全保证。
- 奖励包含爬行姿态、速度跟踪、四肢支撑/摆动、避免滑动、动作平滑；不复用直立双足奖励。
- 禁止头、躯干拖地等取巧方式；不能只看总奖励。
- 建议验收：固定未见种子、100 个 20 秒 episode，至少 95% 无跌倒，前进速度 MAE < 0.05 m/s；检查四肢交替、接触和视频。至少复测 3 个训练种子。
- 未达到门槛不得宣称“稳定爬行”，不得自动启动地形长训练。

### C. 斜坡

- 从平地 checkpoint 开始，坡度依次扩大到 3°、6°、10°、约 16°。
- 随机坡道起点与上下坡方向；机身高度相对局部地面计算。
- 引入地形高度观测，明确这是仿真可用信息，未来真机需传感器或蒸馏。
- 以完整通过率、跌倒率、滑动和速度误差验收；目标至少 90% 通过指定测试坡道。

### D. 上楼与下楼

- 与斜坡分开，先 2–3 cm 台阶，再 5、8、10 cm；随机踏面深度、起点和方向。
- 分别评估上楼、下楼，不把上楼成功当作下楼成功。
- 特别检查摆动清障、前后肢高度差、躯干净空、落地冲击和边缘滑落。
- 各方向独立 100 回合评估，通过率目标至少 90%；混合地形后复测平地性能。
