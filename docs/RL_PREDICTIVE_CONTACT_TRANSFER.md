# 物理预测控制与承重切换验证

## 2026-10-30 状态

**已完成名义条件下右→左连续移脚、扩大站姿、约 2.8cm 的双脚承重下降，以及双手从头顶移到前下方约 60cm 的准备动作，尚未完成站立→双手落地→爬行。** 全局路线审查与最新物理结果见 `RL_TRANSITION_ROUTE_REVIEW.md`；下降结果见 `RL_DOUBLE_SUPPORT_DESCENT.md`。不替换已验证的爬行策略，不发布为实机策略。无后台训练、无提交或推送。

通过的阶段：

1. 站立起步，移重心到右脚，左脚卸载、抬高约 4cm，稳定保持。连续 12.5s，通过原逐 2ms 物理门槛和精确回放。
2. 站立起步，左脚卸载、抬脚、向外移动 4cm 并转向 0.2rad，落脚确认后回移重心、恢复双脚承重并保持。连续 24.24s，通过物理门槛、轨迹回放和独立报告验收。
3. 新增非线性指令复核后，右脚单独移步通过 23.92s；右→左两次移步连续通过 46.96s，无中途重置，独立审计逐 2ms 重新仿真并复核物理门槛通过。
4. 逐步物理重放该已验收前段，再接在线下降控制，整段 58.96s 通过独立重仿真。目标降低 3cm，机身/COM 实际降低 2.846/2.816cm，下降全程双脚持续承重；前段没有直接重置到成功末态。
5. 接入双臂先前移再降低的在线控制，整段 74.94s 通过独立重仿真。双手最终高约 60cm，机身高度变化约 1mm、双脚持续承重；双手仍未着地。

目前是单个名义初始条件下的结果，**不是扰动鲁棒性、任意动作顺序、下降落手或爬行接管的验证**。左→右顺序仍失败，不能忽略该反例。

## 为什么改变方法

- 旧 QP 的八个假定脚底角点不能代替真实接触；换成实测接触后仍可能把几何参考误当成可执行动作。
- 对失败状态审计发现脚—小腿内部接触力可达约 172N。旧动力学方程遗漏内部接触与关节干摩擦。仅将测得的内部力作为滞后前馈补偿也没有解决问题；该实验仍因自碰撞失败，不能宣传为修复完成。
- 宽站姿规划有 31/31 个节点通过当时的几何/静态筛查，但直接插值执行失败。静态路径没有解决脚在地面上如何卸载、移动和重新承重的问题。
- 原参考从名义站姿生成，控制器却在 0.5s 真实接地后启用；启动时 COM/姿态已经改变。直接追旧参考产生瞬间误差。改为从**接地后的实际状态重新规划**后，单脚承重阶段通过。
- 接触切换时，恒扭矩接口会反复抵消原生位置 PD 的偏置项，近似保持 20ms 扭矩。保留原生位置阻尼的预测控制对照更稳定：落脚阶段没有再出现前一接口的力矩失败，但仍需要接触事件门控。

## 实现

- `rl/internal_constraint_force.py`：提取非地面内部接触和关节干摩擦的广义力，仅写入计算数组，不施加外力。测试验证内部力在浮动基上抵消，并与地面反力一起重构 `qfrc_constraint`。
- `rl/predictive_contact_controller.py`：复制完整 MuJoCo 状态，按实际 2ms 执行器接口预测 20ms，有限差分线性化实际响应。候选控制只运行在临时数据中；真实机器人保持连续积分。
- `rl/predictive_position_controller.py`：预测与执行均保持原生位置目标，而不是在每个物理步抵消 PD。保留 80% 请求力矩保护、原生控制范围和实际物理验收。
- `rl/check_single_support_reference.py`：从当前真实状态规划非对称单支撑及移脚参考。脚位、脚朝向、COM、躯干和关节参考来自同一姿态，避免不同任务目标互相冲突。
- `rl/check_predictive_reference.py`：在线规划、执行、接触确认、落脚搜索、记录与完整回放。左脚连续三个 20ms 采样载荷超过 5N 才允许重心回移；丢失载荷时停止推进参考。
- 几何目标到达地面并不保证实测接触。首次位置控制实验在离地约 0.52mm 处等待到超时。加入最大 3mm、速度 1mm/s 的**足端位置参考下探**，用于寻找实际接触；这不修改地面高度、碰撞几何、真实状态或允许穿深。
- 落脚预载与回载目标连续衔接；不在确认接触后突然重新要求卸载。
- QP 约束按量纲缩放，并检查归一化残差，解决一个 `solved inaccurate` 数值停止。缩放不改变约束集合；不可行时的松弛 LP **仅作诊断，不执行松弛解**。

## 2026-10-29：右脚验证与连续移步对照

新增 `rl/check_predictive_step_chain.py`：只在起点重置一次，后续每一步从真实当前状态重新规划；规划前后比较完整 integration state，段间不重置、不拼接。每段必须完成参考、实际抬脚至少 3cm、最终双脚持续承重一秒、脚位/方向达标并收敛。超时不算成功。整条轨迹最后统一重放。

### 控制器改动及单脚结果

- 原左脚流程直接镜像到右脚，在 20.602s 触发高度门槛；不能把左脚成功外推为双侧通用。
- 提高接触确认到 20N/100ms、增加小幅预加载，并没有独立解决问题。等待承重而不改变重心可能停滞，线性化接触控制也可能引起失载。这些尝试的报告及源代码快照均保留，最终没有保留这一组阈值调整。
- 数值层：仅在原 OSQP 不精确收敛时增加对角变量缩放重求解，仍要求 `solved`、原约束残差和非线性碰撞复核通过。仅增加迭代次数的对照无效；不执行诊断 LP 的放松解。
- 控制层：新增可选 `--nonlinear-search`。对 QP 给出的改变量及其缩小版本，用真实 MuJoCo 20ms 预测重新计算同一任务代价，在符合原线性约束及碰撞/关节位置筛查的候选中选择最低代价者。预测只操作 scratch data，不改变真实状态，不施加外力。它是短时控制改进，不是长期稳定性证明。
- 恢复原先的接触检测与回载流程后，**右脚单独移步通过**：报告 `output/rl/predictive_step_chain/2026-10-29_10-54-50-112015/report.json`，23.92s；最终左右脚位置误差 1.07/2.98mm，最后一秒最小载荷 154.79/157.35N，最大总穿深及自碰撞穿深均 0.428mm。
- 新的独立审计 `rl/check_predictive_chain_report.py` 不仅检查报告：还从真站姿重新执行所有保存的控制指令，逐 2ms 比较 qpos/qvel、重新计算物理门槛、载荷与穿深。右脚报告通过；全程 20ms 预测速度误差为零。只验证一个无初始扰动的名义样例。

### 连续组合不能由单步成功推出

左→右第一次组合：第一步通过，第二步规划在落脚附近出现约 1.15mm 自碰撞和 5.44mm COM 目标误差，因此在执行前停止。报告 `output/rl/predictive_step_chain/2026-10-29_10-55-43-964907/report.json`。

规划器原先额外要求 COM 高度不变、水平位置接近脚中心；这不是任务必需的物理约束。新增一个明确记录的几何备选：允许 COM 高度偏离初始参考最多 2cm，要求静力平衡在向内收缩 5mm 的脚底支撑区域中成立，并加强碰撞惩罚。仍保留原物理自碰撞 1mm、总穿深 5mm、力矩、关节和非支撑接触门槛。该备选只在原参考筛查失败后尝试，原失败节点也归档；静态筛查不等于动态可执行。

此备选让第二步参考通过筛查，但**左→右连续物理执行仍失败**：第二次落脚后未稳定保持，41.50s 控制 QP 不可行，此时已明显失稳下落，不能称为只是求解器问题。报告 `output/rl/predictive_step_chain/2026-10-29_11-03-35-196924/report.json`。没有运行爬行接管，也没有宣布完整过渡成功。

### 换序对照：右→左连续通过

不再继续调整接触阈值，保持同一规划/控制配置，只交换动作顺序。报告 `output/rl/predictive_step_chain/2026-10-29_11-06-00-449154/report.json`：

- 从真站姿连续执行 46.96s，共 23,480 个物理步；两段都通过参考完成、实际抬脚、落脚、持续双脚承重、位置/朝向和速度收敛验收。
- 右脚段 0.50–23.92s，左脚段 23.92–46.96s；段间状态、仿真时钟及轨迹索引连续。左脚段使用收缩支撑区域/可变 COM 高度的规划备选，没有对真实状态作几何投影。
- 最终两脚位置误差 1.26/1.19mm，最后一秒最小载荷 156.31/155.83N；最大总穿深和自碰撞穿深均 0.465mm。
- 最终机身线速度约 `2.79e-8 m/s`，角速度约 `4.28e-8 rad/s`；所有已执行控制区间的预测速度误差为零。
- 独立审计通过：重新逐步积分并对比全段 qpos/qvel、重新测量每个物理步的安全门槛、载荷及穿深，不只相信报告的 `passed` 字段。
- 成功样例中没有触发数值缩放重试，因此不能把这次成功归因于增加求解迭代次数。非线性候选复核和动作顺序对照是本轮的主要改进。

这证明在当前模型、当前初始条件下存在一条连续的双脚交替承重/扩大站姿轨迹；**尚不能证明下降落手成功，也不能证明右先左后具有扰动鲁棒性**。下一步从这个真实连续末态接入小幅下降并单独验收，不能把两只脚的成功替代双手接触切换的验证。
