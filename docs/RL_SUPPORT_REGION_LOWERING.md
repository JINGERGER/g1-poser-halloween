## 为什么不再强制 COM 追脚中心

此前对 COM 点目标偏差的限制，把“偏离人为中心点”和“失去承重能力”混在了一起。新增 `--balance-region` 使用内缩 5 mm 的脚底支撑区域，随卸载相位连续收缩到支撑脚，再随落脚相位展开。目标点仍有弱正则，但在区域内允许选择姿态。

求解时额外向区域内部留 2 mm 目标余量，避免软惩罚把解放在边界外。竖直力 LP 同时限制关节力矩 ≤70%；这是离线静力筛选，不代表这些反力已在实际仿真中发生。在线依然使用真实 MuJoCo 预测、实际接触载荷、原碰撞和力矩门槛。

这是一种明确的新参考模式，**没有回头放宽旧报告的点目标标准**。精确参考起点和每节点 0.12 rad 关节增量约束仍启用。

## 如何得到下降段

`output/rl/heel_roll_routes/2026-10-30_13-37-47-742903/report.json` 的 `crouch_close` 路线，截取到 phase=0.55：

1. 从真实 159.84 秒终态规划，不使用另造的低位重置。
2. 针对不对称脚位，手的横向目标以当前脚中心为基准，而不是沿用旧准备姿态的横坐标。
3. 自碰撞优化可按几何体对分别惩罚，避免只取最大穿透导致不同接触对争夺梯度。
4. 执行参考首节点替换为真实当前姿态，检查关节增量及每段 11 点插值的自碰撞、非支撑触地。
5. 保持原预测位置控制器、2 ms 实际物理检查及原脚部承重标准；只把阶段目标从“保持高度”改为“到达明确下降高度”。

初次下降运行在写 JSON 时因 NumPy bool 序列化报错，未作为有效实验报告。显式转换为 Python bool 后，重新从真站立执行整条轨迹并保存上述成功报告，未事后补造结果。

## 落手尚未解决

从新的 42.5 cm 骨盆终态继续比较：

- 放开水平 COM 目标：`output/rl/heel_roll_routes/2026-10-30_13-43-01-932470/report.json`。
- 同时放开足偏航、保留足法向目标：`output/rl/heel_roll_routes/2026-10-30_13-44-33-301558/report.json`。

三种落手/抬跟路线仍未形成完整合格几何路径。放开足偏航时，某些末态手能接近地面，但伴随脚底过度穿透，或双脚悬空、非支撑部位触地；这些没有进入真实执行，更没有被记作接触成功。

后续重点必须是**带有限时域动力学的接触转移**，同时优化足旋转/卸载和双手落地时序。不要再把每个节点静态平衡当成唯一通路；也不要凭“手接近地面”就给悬空手分配力。只有实际承重与原爬行接管验收都通过，才标记完整成功。

### 动态落手对照

`output/rl/dynamic_hand_contact/2026-10-30_13-49-39-424756/report.json`：把上述 free_toe 节点仅作为关节命令建议，分别以 1/2/4 秒执行，不要求中途静态平衡；每次都从真站立回放完整 175.82 秒前缀，然后保持原物理门槛执行，并保存/回放失败轨迹。

- 1 秒命令：176.318 秒左髋俯仰超限约 0.001232 rad，停止。
- 2 秒命令：176.812 秒同一关节超限约 0.002195 rad，停止。
- 4 秒命令：177.560 秒左小腿先触地，非支撑载荷超限，停止。

这不是动态轨迹优化或 RL，只是预先限定规模的速度/接触对照，不能把它失败解读为所有动态路径不可行。它提示需要重新安排足朝向与髋部工作空间，而不只是继续减慢同一轨迹。扩步入口现也允许 `--step-distance 0 --step-yaw ...`，用于显式的抬脚原地转向，不需要把零位移伪装成极小扩步。
