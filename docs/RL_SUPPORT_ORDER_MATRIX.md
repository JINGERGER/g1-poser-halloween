# 起步肢体的配对比较

## 冻结方案

不再预设右后脚最先抬起。两个真实带载初态，各比较四肢支撑对照及左手、右手、左脚、右脚离地，合计10格。
所有格从同一对应初态出发，重新生成各自的静力候选；右脚不享有历史最优候选或额外迭代。
每格固定两阶段：`ContactProblem` 的接触力松弛→`NativeProblem` 的原生接触平衡。
每阶段最多150迭代/90秒，零重启；松弛阶段即使未收敛，也把最后有限候选交给原生阶段，规则对四肢一致。
等预算指相同的时间/迭代上限，不代表问题维度相同或每格必须消耗全部预算。

沿用前轮物理模型、MuJoCo 3.8.0、接触参数、原生平衡及安全门槛，不修改已冻结脚本：

- 原生基座线加速度范数≤0.01m/s²，其余广义加速度绝对值≤0.1rad/s²。
- 候选承重肢各≥10N，目标肢净空≥2cm、载荷≤1N；优化穿透≤4.5mm。
- 通过原生平衡才做3秒假设初始化保持；保持通过才从原带载状态做6秒过渡。
- 重放要求穿透≤5mm、非支撑载荷≤1N、平均承重滑移≤2cm/s、接近限矩端点比例≤10%。
- 保持1秒后/过渡4秒后的所有端点：目标肢无接触、净空≥15mm、载荷≤1N，其他肢各承重>5N。
- 固定0.5秒等待、3秒平滑电机目标变化；不强写实时位姿，不提供外力，不优化时序。

新增独立、按目标肢体索引验收的重放器；不能复用旧函数中固定右脚的三肢判据。
测试覆盖四种目标肢的真/假例、同锚点配对、约束复算、源文件哈希和保存状态重放。
不改变旧实验的源文件，因此已有报告仍可按原哈希复验。

## 解释规则与停止条件

- 找到过渡通过的起步肢体：只证明对应固定初态可卸载/保持，不是已完成落地或爬行。
- 数学平衡通过但保持/过渡失败：分别报告，不能合并为成功率。
- 所有肢体都失败：不追加同一局部搜索，也不宣称机器人不可行；这种单点局部平衡求解本身可能不足。
- 如果四肢对照失败，先检查求解链路，不能直接比较三肢优劣。

不训练RL、不挑中间迭代、不调整验收门槛；输出完整10格结果而不是只展示最好视频。
本轮只比较单肢起步，不等价于搜索完整四肢接触序列。

### 可用的证据：初态2、左脚离地姿态

直接初始化到求解出的零速候选后，只保持原生电机目标，不固定基座或关节，也不施加辅助外力：

- 原生基座线加速度范数5.28e-7m/s²，其余最大广义加速度9.70e-6rad/s²。
- 150次迭代到限，但独立约束验收通过；没有根据solver success误丢弃候选。
- 连续3秒左脚无接触且载荷为0，净空约**13.18cm**；并非执行了一次从地面抬起的动作。
- 其他三肢承重约：左手83.20N、右手47.32N、右脚181.63N。
- 最大穿透4.500mm，最大实际力矩比例0.890，平均承重滑移约1.01e-8m/s。

本轮只要求净空≥2cm，没有设置抬脚上限，因此找到的是高抬脚姿态，不能包装成2cm低幅爬行参考。
它证明的是原模型与执行器在这一**假设初始化**下可以维持一个三肢姿态3秒，
不证明从原姿态可达、对扰动稳定或具备连续爬行/实机能力。

保存轨迹：该目录的 `anchor2_limb2_hold.npz`，模型及候选qpos/ctrl均在同目录报告中。
这可用作后续求解的终端姿态参考，但不是已经验证过的运动示范数据。

### 尚未解决的证据：带载过渡

同一候选从真实原带载状态出发，沿现有平滑目标角插值，在1.54秒触发左手掌5.052mm穿透门槛。
停止时左脚仍承重约57.54N、间隙约-0.707mm；没有完成卸载。
全段最大力矩比例约0.475，不能将失败简单归因于电机打满。
这是固定插值路径失败，不是已证明候选不可达；也不应通过放宽5mm门槛来宣布成功。

## 验证与下一步

通过四种目标肢体判据测试、10格初态配对/源文件哈希/约束重算、6段qpos/qvel独立物理重放（误差≤1e-9）。
源文件未改动前轮实验；右脚和四肢对照复现了前轮结果，没有暗换模型或引擎。

此结果改变主线：**不再把右后脚先抬作为唯一入口，也不继续寻找更多静态姿态。**
下一问题是从原四肢带载状态到已知三肢姿态的接触切换路径。
应把身体移重、目标肢卸载和抬起分阶段求解，并保留全身与原生接触反馈；
不能只把两端关节角插值，更不能在实时仿真中插值qpos。
13.18cm候选只作可承重终点证据，后续还需寻找低净空中间状态与落地/推进，不能直接拿它训练“爬行成功”。
若这条连接路径在预定预算内仍失败，应保留动态控制路线对照，而非把静态三肢可达性变成RL的无限前置条件。
